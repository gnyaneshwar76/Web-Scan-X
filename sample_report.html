web.corsA02:2025 Security Misconfiguration / CWE-942

What it is

The server returned Access-Control-Allow-Origin: https://evil.example with Allow-Credentials: true, so any origin can read authenticated responses (session data, etc.). A too-open CORS policy can let untrusted websites read this site's responses.

How to check it yourself

curl -s -I -H 'Origin: https://evil.example' http://127.0.0.1:61016/ | grep -i access-control — see if the origin is reflected or set to '*'.

Evidence

Origin: https://evil.example  ->  Access-Control-Allow-Origin: https://evil.example; Access-Control-Allow-Credentials: true

How to fix

Allow only an explicit allow-list of trusted origins; never reflect arbitrary origins, and never combine a wildcard/reflected origin with Allow-Credentials.

web.cspA02:2025 Security Misconfiguration / CWE-693

What it is

A CSP is present but has gaps that reduce its protection against cross-site scripting and content injection: 'unsafe-inline' allows inline scripts/styles (defeats much of XSS protection); wildcard '*' source in default-src; no object-src 'none' (plugins/embeds not locked down); no base-uri (allows <base> tag injection).

How to check it yourself

Inspect the Content-Security-Policy response header and review each directive against the OWASP CSP cheat sheet.

Evidence

Content-Security-Policy: default-src *; script-src 'unsafe-inline'

How to fix

Remove 'unsafe-inline'/'unsafe-eval' (use nonces or hashes), avoid wildcard sources, and add object-src 'none' and base-uri 'self'.

  • https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Security-Policy
