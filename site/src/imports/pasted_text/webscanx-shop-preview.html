HIGH

Reflected XSS in ?q parameter

/search?q=<script>alert(1)</script>

WHAT IT IS

The search query parameter 'q' is reflected directly into the response HTML without proper sanitization or context-aware output encoding. An attacker can construct a crafted link that executes arbitrary JavaScript in the victim's browser session.

HOW TO CHECK IT YOURSELF

  1. Send a GET request containing standard script tags in the q parameter.
  2. Inspect the response body to confirm unencoded reflection.
curl -i "https://demo.webscanx.internal/search?q=%3Cscript%3Ealert(1)%3C/script%3E"

EVIDENCE

<div class="query-echo">
Results for: <script>alert(1)</script>
</div>

HOW TO FIX IT

  • Apply context-aware HTML entity encoding prior to outputting values into template HTML bodies.
  • Enforce a Content-Security-Policy header omitting 'unsafe-inline' from the script-src directive.
REFERENCES OWASP A03 · CWE-79

Questions

Does anything get uploaded? +

No. WebScanX runs strictly on your own hardware. Zero telemetry, zero usage tracking, and zero report data ever leave your machine.

Is it legal to scan a website? +

You may only scan websites, web services, or staging environments that you own or have explicit written authorization to test. WebScanX enforces an authorization gate before each scan.

Does it fix vulnerabilities? +

No. v1 finds and explains each issue and shows you how to fix it yourself. It never changes your site.

What does it need to run? +

The standalone binaries have zero external runtime requirements. Just double-click the executable or run it from your command line. Python 3.9+ is required only if installing via pip.

Is it free? +

Yes. WebScanX is completely open-source under the Apache 2.0 license. You can use it freely for personal, research, or commercial infrastructure testing.

HIGH

Reflected XSS in ?q parameter

/search?q=<script>alert(1)</script>

WHAT IT IS

The search query parameter 'q' is reflected directly into the response HTML without proper sanitization or context-aware output encoding. An attacker can construct a crafted link that executes arbitrary JavaScript in the victim's browser session.

HOW TO CHECK IT YOURSELF

  1. Send a GET request containing standard script tags in the q parameter.
  2. Inspect the response body to confirm unencoded reflection.
curl -i "https://demo.webscanx.internal/search?q=%3Cscript%3Ealert(1)%3C/script%3E"

EVIDENCE

<div class="query-echo">
Results for: <script>alert(1)</script>
</div>

HOW TO FIX IT

  • Apply context-aware HTML entity encoding prior to outputting values into template HTML bodies.
  • Enforce a Content-Security-Policy header omitting 'unsafe-inline' from the script-src directive.
REFERENCES OWASP A03 · CWE-79

Questions

Does anything get uploaded? +

No. WebScanX runs strictly on your own hardware. Zero telemetry, zero usage tracking, and zero report data ever leave your machine.

Is it legal to scan a website? +

You may only scan websites, web services, or staging environments that you own or have explicit written authorization to test. WebScanX enforces an authorization gate before each scan.

Does it fix vulnerabilities? +

No. v1 finds and explains each issue and shows you how to fix it yourself. It never changes your site.

What does it need to run? +

The standalone binaries have zero external runtime requirements. Just double-click the executable or run it from your command line. Python 3.9+ is required only if installing via pip.

Is it free? +

Yes. WebScanX is completely open-source under the Apache 2.0 license. You can use it freely for personal, research, or commercial infrastructure testing.
